
## CMS

**¿Qué es?**  
Un CMS (Content Management System) es un sistema que permite crear, administrar y publicar contenido digital, normalmente mediante una interfaz web, sin desarrollar toda la aplicación desde cero.

**¿Dónde lo encuentro?**  
En sitios web y portales que utilizan plataformas como WordPress, Drupal o Joomla para gestionar páginas, usuarios, archivos y contenido.

**¿Por qué me afecta?**  
Un CMS vulnerable, desactualizado o mal configurado puede ampliar la superficie de ataque y permitir acceso no autorizado, ejecución de código o modificación del contenido.

**¿Cómo se soluciona?**  
Mantener el CMS, sus extensiones y temas actualizados, eliminar componentes innecesarios, aplicar controles de acceso y proteger las cuentas administrativas.

**¿Cómo lo usaría un atacante en mi contra?**  
Puede buscar vulnerabilidades conocidas en el CMS o sus componentes para obtener acceso, modificar contenido, robar información o comprometer el servidor.

## Framework

**¿Qué es?**  
Un framework es una estructura de desarrollo que proporciona componentes, reglas y herramientas reutilizables para construir aplicaciones de forma más organizada y consistente.

**¿Dónde lo encuentro?**  
En aplicaciones web, móviles o de escritorio, donde frameworks como Django, Laravel, .NET o Spring proporcionan funcionalidades para desarrollar la aplicación.

**¿Por qué me afecta?**  
Una vulnerabilidad en el framework o una implementación insegura puede afectar múltiples componentes de una aplicación y aumentar su superficie de ataque.

**¿Cómo se soluciona?**  
Mantener el framework actualizado, revisar sus dependencias, aplicar configuraciones seguras y seguir las prácticas de desarrollo seguro recomendadas.

**¿Cómo lo usaría un atacante en mi contra?**  
Puede aprovechar vulnerabilidades conocidas del framework o errores en su configuración para acceder a información, ejecutar acciones no autorizadas o comprometer la aplicación.

## Middleware

**¿Qué es?**  
Middleware es software que actúa como intermediario entre diferentes componentes de una aplicación, procesando solicitudes y respuestas antes de que lleguen a su destino.

**¿Dónde lo encuentro?**  
En aplicaciones web y APIs, donde puede encargarse de autenticación, autorización, registro de solicitudes, manejo de errores o procesamiento de tráfico.

**¿Por qué me afecta?**  
Un middleware mal configurado puede permitir que solicitudes maliciosas evadan controles de seguridad, accedan a recursos protegidos o expongan información.

**¿Cómo se soluciona?**  
Mantener sus componentes actualizados, validar correctamente las solicitudes, aplicar autenticación y autorización y registrar eventos relevantes para su monitoreo.

**¿Cómo lo usaría un atacante en mi contra?**  
Puede intentar manipular solicitudes para evadir controles implementados en el middleware o aprovechar vulnerabilidades que permitan saltarse autenticación, autorización u otras validaciones.
